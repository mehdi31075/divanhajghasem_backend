# بک‌اند دیوان حاج قاسم

نسخهٔ پایه از `assets.zip` کاربر استخراج شده و پیش از تغییر API با commit
`7678bac` ثبت شده است. تمام فایل‌های PHP قدیمی، دارایی‌های پنل و تصاویر
دسته‌ها حفظ شده‌اند. رمز دیتابیس در `includes/variables.php` فقط محلی است و
در Git قرار نمی‌گیرد؛ ZIP همراه CMS نیز از Git حذف شده است.

## سازگاری با اپ اندروید فعلی

اپ اندروید قدیمی فقط خواننده است. **فایل `api.php` عیناً حفظ شده است**:
GET دسته‌ها، مطالب دسته، جزئیات و latest_news بدون توکن باقی می‌مانند؛ wrapper
`AndroidEbookApp`، مقدارهای رشته‌ای، ترتیب و پاسخ خالی `[]` تغییر نکرده‌اند.
مطالب ایجاد/ویرایش/حذف‌شده با توکن، از همین API نیز دیده می‌شوند.

## پنل و اپ جدید با توکن

پنل `index.php` اکنون رابط JavaScript برای همان `mobile-api.php` مورد استفادهٔ
Flutter است. ورود، ایجاد/ویرایش/حذف مطلب، مدیریت دسته و تصویر، و مشخصات حساب
با `Authorization: Bearer` انجام می‌شوند. PHP session و cookie در احراز هویت
پنل مصرف نمی‌شوند. توکن در sessionStorage همین تب نگهداری و هر بار باز شدن
پنل با `me` اعتبارسنجی می‌شود؛ رمز ذخیره نمی‌شود و همه fetchها `credentials:
omit` دارند. خروج توکن را لغو و دادهٔ ورود این تب را پاک می‌کند.

آدرس‌های قدیمی پنل مانند `dashboard.php` و `edit-menu.php?id=...` اکنون همان
رابط توکن را باز می‌کنند. POST به فرم‌های قدیمی و دسترسی مستقیم به PHPهای
`public/` با ۴۱۰ متوقف می‌شود؛ cookie قدیمی مجوز نوشتن نیست. نسخهٔ قبلی پنل
در تاریخچه Git محفوظ است. حالت کوکی قدیمی Flutter برای این بک‌اند بازنشسته
دیگر قابل استفاده نیست؛ حالت پیش‌فرض Flutter از ابتدا توکن است.

API جدید از همان حساب‌ها و هش رمز موجود استفاده می‌کند؛ حساب جدید یا تغییر
رمز اجباری لازم نیست. migration فقط دو جدول auth اضافه می‌کند و schema
جدول‌های قدیمی را تغییر نمی‌دهد. تصویر قبلی هنگام ویرایش دسته نگه داشته
می‌شود مگر تصویر جدید آپلود شود. حذف دستهٔ دارای مطلب با ۴۰۹ متوقف می‌شود؛
ابتدا مطالبش را منتقل یا با تأیید جداگانه حذف کنید.

## نصب روی هاست موجود

1. از فایل‌ها و دیتابیس هاست پشتیبان بگیرید. `migrations/001_token_auth.sql`
   را در دیتابیس موجود اجرا کنید (اگر قبلاً اجرا شده، تکرار امن است).
2. فایل‌های فهرست‌شده در `DEPLOYMENT_FILES.txt` را در مسیر متناظر هاست
   آپلود/جایگزین کنید؛ این بار شامل **ورودی‌های پنل و همه PHPهای public/**
   هم هست تا مسیر قدیمی نوشتن باز نماند. `includes/variables.php` موجود هاست
   و تصاویر موجود `upload/` را نگه دارید. tests، node_modules و .git را
   آپلود نکنید؛ پنل به Node یا build روی سرور نیاز ندارد.
3. تنظیم موجود `includes/token_config.php` را نگه دارید؛ در نصب تازه example
   را کپی کنید. HTTPS برای مدیریت پیش‌فرض لازم است. پشت TLS proxy، متغیر
   HTTPS را در تنظیمات مطمئن هاست فعال کنید؛ هدر دلخواه کاربر ملاک نیست.
4. مطمئن شوید Authorization به PHP/FastCGI می‌رسد. در صورت نیاز با پشتیبانی
   هاست، فقط برای API جدید این تنظیم را اعمال کنید:

   ```apache
   <Files "mobile-api.php">
       SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1
   </Files>
   ```
5. همزمان با انتشار، کش قدیمی مرورگر پنل را تازه کنید. با حساب موجود وارد
   index.php شوید و روی مطلب/دستهٔ آزمایشی CRUD را بررسی کنید؛ اپ اندروید
   قدیمی باید همچنان بدون ورود بخواند. این نسخه خودکار روی سایت deploy نشده.

API جدید به PHP ۵٫۶ یا جدیدتر و mysqli نیاز دارد؛ PHP ۵٫۶ برای توکن تصادفی به OpenSSL نیز نیاز دارد. **نسخه PHP سایت را صرفاً برای
این API ارتقا ندهید**: `api.php` قدیمی از `mysql_*` استفاده می‌کند که در PHP ۷
حذف شده است. تست محلی کد جدید با PHP ۸٫۲ انجام شده؛ سازگاری عملی هاست و MySQL
باید قبل از انتشار تأیید شود.

برای میزبان آزمایشی که فقط HTTP دارد می‌توانید صریحاً `require_https` را
`false` کنید؛ در HTTP رمز و توکن روی شبکه رمزنگاری نمی‌شوند. این گزینه برای
انتشار عمومی مناسب نیست. HTTPS را روی هاست تنظیم و آدرس Flutter را HTTPS کنید.

## قرارداد API

خواندن عمومی بدون توکن و با قرارداد نسخهٔ Android:

| درخواست | نتیجه |
| --- | --- |
| `GET mobile-api.php` | دسته‌ها و مسیر تصاویر |
| `GET mobile-api.php?cat_id=61` | مطالب دسته |
| `GET mobile-api.php?nid=117` | جزئیات مطلب |
| `GET mobile-api.php?latest_news=20` | همان ترتیب صعودی شناسهٔ API قدیمی |

پاسخ خواندن `{"AndroidEbookApp":[...]}` است و در نبود رکورد `[]` برمی‌گردد.
شناسه‌ها و سایر مقدارهای غیر null به‌شکل رشته برمی‌گردند، مثل API قدیمی.
`news_date` **زیرعنوان** است، نه تاریخ ایجاد یا ویرایش.

برای نوشتن از form-urlencoded یا JSON استفاده کنید. تصاویر دسته با multipart/form-data ارسال می‌شوند. توکن فقط در هدر
`Authorization: Bearer <access_token>` ارسال می‌شود؛ query string یا cookie
پذیرفته نمی‌شود. رمز و توکن واقعی را در مثال‌ها یا Git ثبت نکنید.

| درخواست | فیلدها |
| --- | --- |
| `POST ?action=login` | `username`, `password`؛ پاسخ `access_token`, `token_type: Bearer`, `expires_in`, `username`, `ok: true` |
| `GET ?action=me` | هدر Bearer؛ تأیید حساب |
| `POST ?action=logout` | هدر Bearer؛ لغو همین توکن |
| `POST ?action=create` | هدر Bearer و `news_heading`, `news_date`, `cid`, `news_description` |
| `POST ?action=update` | همان فیلدها و `id` |
| `POST ?action=delete` | هدر Bearer و `id`؛ حذف دائمی رکورد |

عملیات پنل نیز به توکن نیاز دارند:

| درخواست | فیلد/نتیجه |
| --- | --- |
| `GET ?action=stats` | شمار واقعی نوشته‌ها و دسته‌ها |
| `GET ?action=posts` | `page`، `q` و `category_id` اختیاری؛ ۵۰ ردیف در صفحه |
| `GET ?action=account` | نام کاربری و ایمیل؛ بدون هش رمز |
| `POST ?action=account_update` | `email`؛ برای تغییر رمز `old_password`, `new_password`, `confirm_password` |
| `POST ?action=category_create` | `category_name`, `author` و فایل `category_image` |
| `POST ?action=category_update` | همان فیلدها و `id`؛ فایل تصویر اختیاری |
| `POST ?action=category_delete` | `id`؛ فقط دستهٔ خالی |

تصویر JPEG، PNG یا GIF معتبر تا ۵ مگابایت با نام تصادفی ذخیره می‌شود. فایل
قبلی حذف نمی‌شود تا خواننده‌ها و کش قبلی تصویرشان را از دست ندهند. فرم‌های
پنل در خطای ورود متن واردشده را نگه می‌دارند. در پاسخ نامشخصِ نوشتن، دکمهٔ
بررسی نتیجه فقط می‌خواند و POST خودکار تکرار نمی‌شود. تا تعیین نتیجه، متن
فرم قفل است؛ ترک فرم/بستن تب با تغییرات نهایی‌نشده تأیید می‌خواهد. پیش‌نویس
پنل در حافظهٔ صفحه است و مثل پیش‌نویس SQLite اپ، ذخیرهٔ دائمی ندارد.

ویرایشگر CKEditor همراه پنل قبلی استفاده می‌شود. پیش‌نمایش HTML داخل iframe
sandbox بدون اسکریپت است و عنوان/دسته‌ها به‌صورت متن escape می‌شوند. تغییر
عنوان یا دسته، بدون ویرایش بدنه، HTML اصلی را حفظ می‌کند.

عملیات نوشتن موفق `{"ok":true,"nid":"..."}` برمی‌گردانند. ویرایش بدون تغییر
نیز موفق است؛ حذف شناسهٔ قبلاً حذف‌شده موفق می‌ماند. فایل تصاویر در حذف با API
جدید پاک نمی‌شود تا فایل مشترک یا نام نامعتبر از filesystem حذف نشود.

خطا: `{"ok":false,"error":"...","message":"..."}` با status معتبر:
۴۰۱ ورود نامعتبر/منقضی، ۴۲۲ ورودی نامعتبر، ۴۰۴ عملیات/مطلب ناموجود، ۴۰۵ روش
اشتباه، ۴۲۶ نیاز به HTTPS، ۴۲۹ محدودیت تلاش ورود، ۵۰۰ خطای داخلی/migration.
خطای ۴xx قبل از تغییر رکورد صادر می‌شود. قطع ارتباط یا ۵xx بعد از درخواست
نوشتن، دلیل ارسال دوباره نیست؛ ابتدا از API نتیجه را بخوانید.

توکن ۳۲ بایت تصادفی رمزنگاری‌شده است، فقط هش SHA-256 آن روی سرور ثبت می‌شود.
خروج همین توکن را لغو می‌کند؛ انقضا، حذف حساب یا تغییر رمز پنل توکن را نامعتبر
می‌کند. ورود ناموفق پس از ۱۰ تلاش از یک IP در ۱۵ دقیقه محدود می‌شود.
در هاست پشت proxy اشتراکی، REMOTE_ADDR ممکن است IP خود proxy باشد؛ برای
اعتماد به IP واقعی فقط تنظیمات مطمئن هاست را به‌کار ببرید.

API جدید CORS و OPTIONS برای خواندن و هدر Bearer دارد و cookie مصرف نمی‌کند.
Flutter باید برای آن client بدون `withCredentials` استفاده کند. CORS فایل
قدیمی عمداً تغییر نکرده است.

محدودیت‌های schema قدیمی: عنوان ۵۰۰ نویسه، زیرعنوان ۲۵۵ نویسه و بدنه TEXT
حداکثر ۶۵۵۳۵ بایت UTF-8. ایموجی و دیگر نویسه‌های چهار بایتی به‌دلیل charset
قدیمی با خطای روشن رد می‌شوند. HTML بدون بازنویسی ذخیره می‌شود؛ API sanitizer
جدید HTML ندارد. کنترل اتمیک تعارض، idempotency و تاریخ‌های نوشته‌ها اضافه نشده‌اند.

## بررسی محلی

برای تست‌های PHP از PHP ۸ و PDO SQLite، و برای DOM از Node ۲۰ یا جدیدتر استفاده کنید:

```sh
php tests/mobile_api_test.php
php tests/panel_api_test.php
php tests/legacy_reader_test.php
php tests/panel_routes_test.php
npm ci --ignore-scripts
npm test
# اگر php در PATH نیست: DIVAN_TEST_PHP=/path/to/php npm test
```

تست‌ها منطق توکن و SQL تولیدی را با SQLite fixture بررسی می‌کنند؛ همچنین
خود api.php قدیمی را با shim فقط‌خواندنی mysql_* اجرا می‌کنند و دادهٔ ایجاد،
ویرایش و حذف با توکن را بدون ورود از آن می‌خوانند. تست DOM ماژول‌های واقعی
پنل را با API mock اجرا می‌کند. تست‌ها جای MySQL واقعی هاست، آپلود واقعی
تصویر، نمایش ویرایشگر در مرورگر یا تست روی گوشی قدیمی را نمی‌گیرند. هیچ
backend server محلی شروع نمی‌شود و سایت تولیدی تغییر نمی‌کند.
